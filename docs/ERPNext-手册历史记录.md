# ERPNext 手册历史记录

此文件只保留会影响后续安全操作的长期经验。生产数据、用户/客户资料、交易编号、完整 SHA、备份内容和凭据不归档在此。

## 长期安全经验

- **生产写入需要独立回读**：脚本在当前进程里读到自身写入，不代表事务已经提交。写入脚本应明确提交；从新进程重新读取目标记录后才能报告完成。
- **上线要保护现场**：先备份，再记录原 commit 与文件状态；只部署精确差异。不要覆盖不明的生产改动，也不要把全量迁移/安装钩子当作部署默认项。
- **服务加载状态要独立确认**：Python/hook 变更可能被常驻进程缓存。按变更类型重启必要服务并回读进程/页面/API；不要为重启去杀数据库、Redis 或不相关进程。
- **历史库存通过原生单据保护**：有库存或交易关联的 Item/Variant 不直接删除、重命名或 SQL 改账。保留旧记录，使用 ERPNext 原生库存单据迁转，并核对迁转前后数量、仓库和估值。
- **价格只通过 DocType API 改差异**：先列出精确目标、排除模板及停用项，备份并预览；写入后回读 Item Price、币种和 UOM。不要用 SQL 直接改价。
- **附件字段要幂等**：图片直接关联目标 Attach Image 字段；写入前检查既有关联，避免同一文件生成普通附件与字段附件两条关系。
- **共享条码与固定色号是不同身份**：模板保存唯一原包装条码；颜色 Variant 使用继承的标签条码，SKU 不冒充条码。固定色号依据实物确认，保留前导零，不从颜色名称猜测。
- **xPos 身份与凭据分离**：收银员账号负责业务归属，专用同步账号负责传输，Hub 才持有受保护同步凭据，Till 不保存云端密钥。同步失败保留队列，不删除业务记录来“清理”错误。
- **测试覆盖共享分支**：一个公共计划/解析函数可能同时接收 Document、字典或多种目标类型；每条入口分支都需覆盖。预览错误应在任何写入前发生。
- **生产结果分层汇报**：本地测试、文件一致、配置回读、页面/API 行为是不同证据。未完成的层级明确标出，不以命令执行、文件上传或工具返回代替实际业务验证。
