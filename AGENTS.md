# Solua ERPNext agent rules

## Preserve form loading entrypoints

- Before deploying `hooks.py` or wholesale form scripts, run `node my_custom_app_example/solua_home/tests/wholesale_forms_check.cjs`. The check covers the active loader, cache version, release whitelist, and bulk quantity behavior; a failure blocks deployment.
- Compare candidate `doctype_js` with live production before writing. Never overwrite production `hooks.py` with an older whole-file copy; merge only the task's intended entries and preserve other production changes.
- Sales Order, Delivery Note, and Pick List use `wholesale_forms_additional_notes_loader_v17.js` in the local source, loading `wholesale_forms_stock_entry_v20261006.js?v=stock-entry-tools-20261006a`. Read back the live production entrypoint before deployment. A deliberate loader upgrade must update hooks, loader, release whitelist, and the entrypoint check together. Use a new filename/cache version and verify the actual served script and draft Sales Order tools menu after deployment.

## Production backup path: STOP before writing

- `sites/erp.solua.one/private/backups/` is reserved exclusively for Frappe/Bench-generated backup files. Agents, scripts, and people must never create subdirectories or place manual snapshots/rollback copies there.
- Before any production write, verify the exact target path is not under `private/backups/`. Store every manual snapshot only under `private/deployment_snapshots/<YYYYMMDD-task>/`.
- If any directory is found at the top level of `private/backups/`, stop creating snapshots and do not run Bench backup until its owner confirms completion. Then verify ownership, open handles, timestamps, and content hashes; atomically move it intact to a new, conflict-free directory under `private/deployment_snapshots/`. Never delete or merge it.
- Make one complete four-part Bench backup (config, database, public files, private files) at the start of each production release batch and verify all four files exist and are non-empty. That recovery point covers the batch's code sync, migrate/build/cache/restart, and acceptance. Do not imitate Bench backups with manual folders or repeat full backups per file/test.
- A4 designer format writes are create-only; failed validation/rendering must roll back the database transaction. Do not take a full Bench backup per new format. Future changes must clone/save a new format version, never overwrite in place. Take another full backup only for a new release batch, database migration, or an invalidated recovery point after a major production change.

- Read `ERPNext 定制开发操作手册.md` before ERPNext business or production work.
- On production `qq`, keep `sites/erp.solua.one/private/backups/` limited to ordinary files generated by `bench backup`.
- Put manual rollback copies, Print Format snapshots, and deployment artifacts under `sites/erp.solua.one/private/deployment_snapshots/<date-task>/`; never create subdirectories inside `private/backups/`.
- If directories already exist in `private/backups/`, do not delete them. Verify exact paths and ownership, then move them intact to `private/deployment_snapshots/` only when no concurrent operation owns them.
- Create one complete four-part Bench backup (config, database, public files, private files) at the start of each production release batch; verify all four files are non-empty. Reuse that recovery point for the batch's code sync, migrate/build/cache/restart and acceptance; do not repeat a full backup for each file or test.
- A4 designer saves are create-only and rely on database transaction rollback if validation/rendering fails; do not make a full Bench backup for each new format. Future format changes must clone/save a new version, never overwrite in place. Make another full backup only for a new release batch, database migration, or when the recovery point is invalidated by a major production change.
- Do not report a deployment complete until the production page or API behavior has been read back and verified.
